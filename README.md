# AgentReady

> **The public adversarial benchmark for AI agents.** We scan every famous open-source AI agent against OWASP ASI-2026, name and shame the failures, then auto-fix them with formal verification, chaos engineering, and a live PR. Powered by AMD MI300X.

## What it does

Submit any AI agent's GitHub repo and AgentReady returns:

1. **A position on the public leaderboard** — ranked against every famous open-source AI agent (Aider, Open Interpreter, AutoGPT, BabyAGI, Claude Engineer, GPT-Engineer, AutoGen, CrewAI, LangGraph, AgentGPT) on OWASP ASI-2026.
2. **An OWASP ASI-2026 compliance scorecard** with 0-100 scores across all 10 agentic risk categories.
3. **A chaos resilience report** showing the Reliability Surface R(k, ε, λ) under realistic production failures.
4. **A formal verification proof or counterexample** generated by Z3 SMT solver against the agent's declared safety contract.
5. **A digital twin behavioral report** showing the agent's behavior over 7 simulated business days inside enterprise replicas.
6. **An auto-generated GitHub PR** with patched system prompts, a fine-tuned LoRA adapter, an OpenTelemetry config, and a signed compliance certificate.

## Architecture

```
┌────────────────────────────────────────────────────────────────┐
│ INPUT: Public leaderboard (pre-scored) | User-submitted repo  │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼
┌────────────────────────────────────────────────────────────────┐
│ INGEST LAYER                                                   │
│ Clone repo • detect framework • extract tools/prompt/memory    │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼
┌────────────────────────────────────────────────────────────────┐
│ EVALUATION ORCHESTRATOR (LangGraph) on AMD MI300X 192GB         │
│                                                                 │
│  Integration   Quality        Red Team                          │
│  (Twins)       (500x parallel) (OWASP ASI Top 10)               │
│                                                                 │
│  Chaos         Verification   Memory Poisoning                  │
│  (Faults)      (Z3 SMT)       (ASI06 demo headline)             │
│                                                                 │
│  Powered by Llama 3.1 70B Judge + Qwen 2.5 7B Red,              │
│  both running concurrently in 192GB VRAM (impossible on H100)   │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼
┌────────────────────────────────────────────────────────────────┐
│ SCORER + PUBLIC LEADERBOARD UPDATE                             │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼
┌────────────────────────────────────────────────────────────────┐
│ REMEDIATION: prompt patches • LoRA adapter • Z3 contract •     │
│ OTel config • Auto-PR via GitHub API • Signed certificate PDF  │
└────────────────────────────────────────────────────────────────┘
```

Why this configuration requires AMD MI300X: serving the 70B Judge LLM (~90GB FP8) and the 7B Red LLM (~15GB BF16) and the target agent's model concurrently in a single GPU's VRAM is the entire reason the parallel red-team-and-judge pipeline is feasible. On an 80GB H100 you cannot host all three simultaneously without quantizing the Judge below the quality threshold.

## Quick start

### Prerequisites

- Python 3.11+
- Node 20+
- Docker + Docker Compose
- AMD MI300X via [AMD Developer Cloud](https://www.amd.com/en/developer.html) (or any GPU with ≥48GB for a degraded local run)
- A GitHub personal-access token with `public_repo` scope
- A HuggingFace token (free tier is fine)

### Setup

```bash
git clone https://github.com/YOUR_USERNAME/agentready.git
cd agentready
cp .env.example .env
# Fill in GITHUB_TOKEN, HF_TOKEN, etc.
docker-compose up -d              # Postgres, Langfuse
uv sync                            # Install Python deps
cd apps/web && pnpm install        # Frontend
```

### Run

```bash
# Start the Judge LLM (Llama 3.1 70B FP8)
docker run --rm -p 8001:8000 --device=/dev/kfd --device=/dev/dri \
  rocm/vllm-omni:latest \
  --model meta-llama/Llama-3.1-70B-Instruct --quantization fp8

# Start the Red LLM (Qwen 2.5 7B BF16)
docker run --rm -p 8002:8000 --device=/dev/kfd --device=/dev/dri \
  rocm/vllm-omni:latest \
  --model Qwen/Qwen2.5-7B-Instruct --dtype bfloat16

# Start the API
uvicorn apps.api.main:app --reload --port 8000

# Start the frontend
cd apps/web && pnpm dev
```

Visit `http://localhost:3000` to see the leaderboard.

### Run a scan

```bash
curl -X POST http://localhost:8000/evaluate \
  -H 'Content-Type: application/json' \
  -d '{"github_url": "https://github.com/yoheinakajima/babyagi"}'
```

## Repository layout

| Path | What it does |
|---|---|
| `apps/api/` | FastAPI backend — orchestrator, ingest, GitHub PR generation |
| `apps/web/` | Next.js frontend — public leaderboard + per-agent report pages |
| `agents/` | The 8 evaluation agents (Integration, Quality, Red Team, Chaos, Verification, Memory Poisoning, Multimodal, Remediation) |
| `owasp_asi/` | One module per ASI category (ASI01–ASI10) + Crescendo multi-turn attack templates |
| `chaos/` | Fault injection proxy + Reliability Surface R(k, ε, λ) computation |
| `verification/` | Z3 SMT engine + property templates + certificate PDF generator |
| `digital_twins/` | Salesforce, Stripe, helpdesk, Jira, Slack twin APIs (MindsDB-backed) |
| `finetuning/` | Unsloth on ROCm — chaos remediation LoRA adapter pipeline |
| `leaderboard/` | Batch runner + score aggregator for the public leaderboard |
| `infra/` | Dockerfiles + Akash deploy manifests |
| `scripts/` | Operational helpers — leaderboard batch, certificate gen, BiP post drafter |

See [`docs/`](./docs/) for architecture, methodology, and the demo script.
